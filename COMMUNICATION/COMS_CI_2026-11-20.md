# COMS CI, 2026-11-20


## CI gates added, 2026-11-20

`.github/workflows/coms-tests.yml` now runs two jobs on every push and PR, both against a
broker on `127.0.0.1` so neither touches the production bus at `192.168.2.52`.

- **acceptance suite (ubuntu)** - `COMMUNICATION/test_coms_linux.sh`, 24 checks, 0 skipped.
- **bundled transport + 500 KB (windows-latest)** - runs `verify_coms_windows.ps1` under real
  Windows PowerShell 5.1 and fails the build unless the payload comes back as
  `500000 of 500000` bytes, the script exits 0, and no transport or 500 KB test was skipped.

Two defects were found only because the jobs had to run on a clean machine, and both had been
invisible when the same script ran by hand on a host inside the LAN:

1. `choco install mosquitto -y` exits 0 on `windows-latest` and leaves **no** `mosquitto.exe`
   behind, so the broker step now downloads the newest win64 installer from
   `mosquitto.org/files/binary/win64/` and installs it silently.
2. `coms.ps1` honours `COMS_BROKER`/`COMS_PORT`, but the job did not set them, so `check`,
   `topics` and `send` all dialled `192.168.2.52` and failed on a runner that cannot reach it.
   The verify step now sets both.

The Windows gate deliberately allows the `check lists notes` skip: a fresh runner has no note
history, which is unrelated to what that job proves. A skipped transport or 500 KB test is still
a hard failure, so the path stays proven rather than proven once.
